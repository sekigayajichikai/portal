# Google Drive からの自動取り込み（計画）

作成 2026-10-26。**計画・設計のみ（未実装）**。第1段階の実装に入るときに、この文書を仕様として使う。

## 目的

毎月、Drive の共有フォルダに置かれる「関ヶ谷だより」「会報ふれあい」の PDF を、人が「PDFを追加」を押さなくても
翌朝までに **その月の号（下書き）に記事として入っている** 状態にする。
はなの作業は「記事を読んで直す → 確認を依頼 → 承認後に公開」だけになる。

関ヶ谷だより・会報ふれあい以外のファイル（学校だより、チラシ、音声、旧版）は自動では触らない。
それらは「プール」（Drive の中身の一覧）として見せ、取り込む・題名・発行元・区分は人が決める（第2段階）。

## 前提（2026-10-26 にはなと確認）

- 共有フォルダの直下に **月フォルダ**（`202611` のように年月6桁）。その中に PDF。画像は `pic` フォルダ
- PDF のファイル名には **媒体名が入っている**（「関ヶ谷だより」「会報ふれあい」）
- PDF が置かれるのは **毎月25日前後**（第4日曜の「合同会議」の3日前ごろが印刷の締切）
- 通知先: **sekigaya.dx@gmail.com**
- Drive には要らない音声データや更新前のデータが重複して入っていることがある → 自動で触るのは媒体名で判定できる2本だけ
- 今の本番の記事化は **Claude Haiku**（`ai-proxy` 経由。`aiService.extractArticlesFromPDF` は anthropic / openrouter の2択で Gemini の経路は無い）。
  Gemini の無料枠を使っているのは **予定（カレンダー）の抽出** と **週次配信の紹介文**。
  記事化を Gemini にした比較（2026-09-28、`AIコスト・モデル方針.md`）では転記の忠実さが落ちた（81%）ので、自動取り込みでも既定は Claude、切替できる器だけ用意する

## 全体の流れ（第1段階）

1. **毎朝 7:00（日本時間）に GitHub Actions が起動**（手動実行もできる）。Drive の一覧を見るだけなら費用も時間もかからないので毎日でよい
2. 月フォルダ（今月と来月。例: 10/26 なら `202610` と `202611`）の中で、名前に「関ヶ谷だより」または「会報ふれあい」を含む PDF を探す
3. 取り込み済みかを **取込記録（`drive_imports`）** で確かめる。Drive のファイルID と内容の指紋（md5）が一致すれば飛ばす
   - 同じファイルIDで md5 が違う（Drive 側で差し替えられた）→ 自動ではやり直さず「更新あり」として記録し、通知に書く。やり直すかは人が決める（第2段階のプール画面で「差し替え」）
4. 月フォルダ名から号を決める（`202611` → 「2026年11月号」）。無ければ **下書き** で作る。手で作ってあればそれに足す
5. PDF を Supabase Storage に保存し、題名・号数・発行元を AI で読んで（`extractPDFMetadata`）、`source_pdf_urls` に **type: 'source'（PDF版で読む）** で登録。サムネイルも作る
   - 同じ md5 の PDF がすでにその号にあれば（手で足してあった）登録しない
6. 記事化: 本番と同じ `extractArticlesFromPDF` → `dedupeExtractedArticles` → 号に記事を保存（今の「確定して記事を抽出」と同じ結果）
7. **通知**: sekigaya.dx@gmail.com にメール（「2026年11月号: 関ヶ谷だより 13記事・会報ふれあい 6記事を取り込みました。確認してください」＋管理画面へのリンク）。
   失敗したときも必ずメール（何が失敗したか・どこを見るか）
8. 管理画面の「今月の流れ」に「自動で取り込んだ記事を確認（19件）」の段を出す（取込記録を読むだけ）

ここから先は今まで通り人の手: 記事を直す → 「確認を依頼」→ 承認 → 「公開する」。**自動では公開しない。承認・削除も自動ではしない。**

## どこで動かすか

| 案 | 仕組み | 良い点 | 弱い点 |
|---|---|---|---|
| **GitHub Actions（採用）** | リポジトリの `scripts/drive-import/` に置いた Node スクリプトを定期実行。`scripts/schedule-test/run-gemini.mjs` と同じ作り方で、本番の記事化コード（プロンプト・重複除去）をそのまま読み込む | 1本 1〜3分かかる AI 処理でも時間制限がない。PCで `node` で試せる。無料枠で足りる | 失敗の記録は GitHub の「Actions」タブ（見る場所が1つ増える。メール通知で補う） |
| Supabase Edge Function + pg_cron | LINE 連携・週次配信の予約と同じ場所 | 置き場所がまとまる | 1回の実行時間に上限があり、記事化の 1〜3分が収まらないことがある |
| Vercel Cron | サイトと同じ場所 | 設定が少ない | 無料プランは関数が10秒で切られるので記事化は無理 |

Drive へのアクセスは **サービスアカウント**（Google が発行する機械用のアカウント）。共有フォルダをそのアカウントに「閲覧者」で共有する。
人が Google にログインする必要は無い。第2段階のプール画面も同じアカウントで Drive を読む（Edge Function 経由）。

## データ

取込記録 `drive_imports`（新規テーブル。SQL は実装時に `sql/migrations/` に置く）

| 列 | 内容 |
|---|---|
| id | uuid |
| drive_file_id | Drive のファイルID |
| drive_name | ファイル名（取込時点） |
| drive_md5 | 内容の指紋。差し替え検知に使う |
| drive_modified_at | Drive 側の更新日時 |
| month_folder | `202611` |
| kind | `source`（記事にする）／`attachment`（PDFのまま）／`image`（pic） |
| newsletter_id | 入れた号 |
| pdf_url | Storage の URL |
| articles_created | 作った記事の数 |
| status | `imported` ／ `updated`（Drive 側が新しい）／ `failed` ／ `skipped` |
| error | 失敗の理由 |
| imported_at | 取り込んだ日時 |

## 第2段階（プール画面）

号を開いたところに「Drive から取り込む」ボタン → Drive の月フォルダの一覧。

| 列 | 内容 |
|---|---|
| ファイル | 名前・更新日時・種類。PDF と画像以外（音声など）は出さない |
| 状態 | 未取込 ／ 取込済み（日付）／ **取込後に更新あり** ／ 旧版あり |
| 題名・発行元・区分 | AI の提案を初期値に入れ、人が直してから「取り込む」。区分は 自治会（記事にする）／ 地域（PDFのまま） |
| 操作 | 取り込む ／ 更新版に差し替える（古い版は残し、公開側には新しい方を出す） |

- `pic` フォルダは既存の **保留画像**（`pending_images`。PDFから切り出した画像を記事に付けるまで置く場所）に取り込み、今ある「画像の割り当て」画面でそのまま記事に付ける。4コマ漫画もここから
- Drive の一覧と取り込みは Edge Function（サービスアカウントで Drive を読む）。一覧だけなら数秒、PDF 1本の取り込みも数秒で、Edge Function の時間制限に収まる（AI の記事化は呼ばない）

## はな側の準備（第1段階の前に。手順は `Drive取り込み-Google設定手順.md`）

1. Google Cloud でプロジェクトを1つ作り、Drive API を有効にする
2. サービスアカウントを作り、鍵（JSON）を1つ下ろす
3. 共有フォルダをサービスアカウントのメールアドレスに「閲覧者」で共有する
4. 共有フォルダの URL（末尾のID）を教える
5. GitHub の portal リポジトリに Secrets を登録する（サービスアカウントの鍵、Claude のキー、Supabase の URL と service role キー、通知用 Gmail のアプリパスワード）

## 費用・運用

- 記事化: Claude Haiku で号あたり ¥10 前後（今の手動と同じ）。メタデータ読み取りは数円。GitHub Actions は無料枠内
- 失敗したら: メールに理由が届く。GitHub の「Actions」タブ → 失敗した実行 → ログ。手で「PDFを追加」すれば今まで通り進められる（自動取り込みは後から同じ md5 を見て飛ばす）
- 止めたい: GitHub の Actions タブで workflow を「Disable」。コードは残る

## リスク

| こうなるかも | 対策 |
|---|---|
| 同じ PDF を手でも足して二重になる | md5 で同じものは登録しない |
| Drive 側で PDF を差し替えたのに古い記事のまま | 「更新あり」を通知し、人が差し替えを決める（自動でやり直さない。直した記事が消えるため） |
| AI の読み取りが悪い | 下書きのまま人が直す（今と同じ）。モデルは `CLAUDE_MODEL` 1か所で変えられる |
| 月フォルダの名前が違う（`2026-11` など） | 6桁の年月だけ見る。合わないフォルダは無視して通知に「見つからなかった」と書く |
| Actions が止まっていて気づかない | 25日〜月末に新しい PDF が無いときも「新着なし」をメールする（毎日ではうるさいので、この期間だけ） |
