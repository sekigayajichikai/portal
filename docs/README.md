# docs/ — 現役の文書

| 文書 | 内容 |
|---|---|
| `カレンダー抽出ルール.md` | 回覧板の記事・PDF から予定カードを AI 抽出するルール（種別・性質・締切・対象者・参加費・除外条件） |
| `週次配信.md` | 公式LINE「今週のお知らせ」を自動で組み立てる仕組み（配信は締切基準、件数上限、追加抽出の手順、Flexカードでの直接配信） |
| `リッチメニュー.md` | 公式LINEのリッチメニューを管理画面から作り、人によって出し分ける（登録促進／通常／防災訓練タブ） |
| `マスタ管理.md` | 管理画面「マスタ」タブ（会場・団体）。主催団体と発行元は2026-10-01に団体マスタへ一本化。別名→正式名の自動置き換えで表記と誤字を揃える |
| `カレンダー連携.md` | 予定タブから自治会カレンダー（calendar_events）へ予定を載せる。差分を確認して反映。カレンダー側の団体フィルタで予定が消える落とし穴も記載 |
| `予定管理-設計.md` | **設計のみ（未実装）**。予定カードを号をまたいで一覧・編集する「予定」タブ。記事リンクを全号から選ぶ、重複の警告と統合、編集ダイアログの一本化 |
| `記事機能-設計.md` | 関ヶ谷レポート（イベントレポート記事）の設計と進捗 |
| `記事作成のAIコスト相場.md` | 記事1本を AI に書かせた場合のトークン数と費用の目安 |
| `AIコスト・モデル方針.md` | 抽出に使う AI（Gemini 無料枠が既定、Claude はフォールバック）の選定理由と実測 |
| `UX改善提案.md` | 管理画面を「自分以外も使える」ようにする改善リストと対応状況 |
| `UI評価・改善計画.md` | 役員・事務局へ引き継ぐ前のUI評価（つまずく点）と、フェーズ0〜3の改善計画（book-system 統合案を含む） |
| `用語集.md` | 画面に出す言葉の統一表（回覧板・予定・予約・取り込み など）。portal・book-system 共通。文言を書くときはこれに合わせる |
| `SECURITY-MIGRATION.md` | AI キーをサーバー側（Edge Function）へ移した手順（2026-07）。残課題は下の文書へ引き継ぎ |
| `セキュリティ-RLS.md` | **データベース本体を守る話**。公開鍵1本で全部書き換えられた状態から、ログインを本物にして行単位の保護を入れるまで。両アプリ共通 |
| `articles/` | レポート記事の原稿 |

抽出のテスト態勢は `scripts/schedule-test/README.md`、DB の手順は `sql/README.md` を参照。
