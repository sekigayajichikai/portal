# 事業化の構想（複数自治会への展開）

2026-10-12 の相談の記録（同じ日に `/btw` で聞いたメモも合わせた）。調査の中身は `市場調査.md`。
きっかけ: 隣の**夏山自治会**から「バス時刻表をうちにも入れたい」と言われた。
関ヶ谷自治会と夏山自治会は仲が良く、将来は裏方の運営（バックオフィス）をまとめる案も出ている。
こういうきっかけをつかみつつ、**ビジネスの種として広げたい**。そのためには、**複数の自治会で使っても管理・保守の手間を最小にする**ことが前提になる。

---

## メモ: Jカーブ型の成長の条件（判断の物差し）

Jカーブ = 最初は赤字や伸び悩みで沈み、ある点を越えると急に伸びる成長の形（スタートアップ型）。
対して、1件ずつ売って積み上げる事業は、まっすぐ緩やかに伸びる（スモールビジネス型）。どちらが良い悪いではなく、**狙う形で作り方・お金の集め方が変わる**。

新しい案は、次の3つのどれに当てはまるかで「Jカーブになりうるか」を見る。

| 条件 | 意味 | 例 |
| --- | --- | --- |
| **使う人が使う人を連れてくる** | 口コミ・紹介・グループへの招待で、売り込まなくても広がる | 親どうし・夫婦でおたより AI を勧め合う。LINE グループに招待する |
| **使う人が増えるほど価値が上がる** | データやネットワークが効き、後から来た人ほど得をする。真似しにくくなる | 地域の予定データ、移動の需要データ、束ねた自治会の配信網 |
| **1回の契約で大量に入る** | 自治体・連合会・大手との提携で、まとめて配られる | 自治体と契約してその中の全自治会へ |

どれにも当てはまらない案は、良い事業でもスモールビジネス型として計画する（無理に急成長を狙わない）。7 の各案はこの物差しで評価した。

## 1. ビジネスの種になる可能性

売っているのは「バス時刻表」ではなく、**住民がもう友だち登録している公式LINEを、地域の窓口として動かす仕組み**。
バスはその窓口を毎日開いてもらう理由（入口）になる。

### ① 自治会向け「公式LINE運用パッケージ」（月額のサービス）
- 中身: 名簿登録・回覧板・週次のお知らせ配信・お問い合わせ受付・リッチメニューの出し分け・バス時刻表・ごみの日など、今あるものをまとめて提供する。
- 相手: 公式LINEを作ったが運用できていない自治会や、これから作る自治会。
- 強み: 役員が毎年替わっても回る（仕組みが覚えていて、人に頼らない）。導入した自治会どうしで改善を分け合える。

### ② 自治会の裏方業務の共同化（事務局代行・BPO）
- 中身: 名簿の管理、会費の集金・記録、回覧板づくり、問い合わせの一次対応、配信作業などを、複数の自治会からまとめて引き受ける。今回話に出ている「バック業務をまとめる」案そのもの。
- 強み: 仕組み（①）を使えば1人で何自治会も回せる。AI で回覧板の記事化・予定の抽出はもうできている。
- 形: 自治会から業務委託費を受け取る。①を使う権利は込みにする。

### ③ 行政・連合町内会・区役所向けの「地域への配信の道」
- 中身: 区や連合町内会からのお知らせ（防災・イベント・制度）を、各自治会の公式LINEにまとめて届ける。どれだけ読まれたかも返す。
- 価値: 行政は「回覧板が届かない・読まれない」ことに困っている。自治会ごとの公式LINEを束ねれば、確実に届く道になる。
- 形: 区の委託事業、地域活動・DX の補助金。

### ④ 防災・見守り（安否確認・要支援者の把握）
- 中身: 災害時の安否確認（「無事です」ボタン）、避難所の情報、要支援者名簿の更新の声かけ、防災訓練の出欠など。
- 価値: 自治会にとってほぼ義務で、行政の補助の対象にもなりやすい。名簿と LINE がつながっていることが強み。

### ⑤ 地域交通の利用データ・地域交通の相談（交通事業者・自治体向け）
- 中身: どのバス停の時刻表が、いつ・何人に見られているかの集計（個人が特定できない形）。
  コミュニティバスやデマンド交通の需要把握、ダイヤ改正の住民への周知の代行にも使える。
- 価値: 交通事業者や区は「実際に誰が乗りたいか」のデータを持っていない。
- 注意: 集計だけを渡し、名簿の情報とは結びつけない（規約と住民への説明が必要）。

### ⑥ 地域の店・事業者の告知枠（地域メディア）
- 中身: 回覧板・週次のお知らせ・関ヶ谷レポートに、地域の店・教室・医院のお知らせ枠を設ける。
- 価値: 地域の住民だけに確実に届く広告は少ない。自治会の収入にもなり、導入の後押しになる。
- 注意: 自治会の中立性。載せる基準を決めておく。

### ⑦ 似た団体への横展開
- 相手: マンションの管理組合、PTA・子ども会、商店会、老人会、地域のスポーツ団体。
- どれも「名簿・連絡・出欠・会費・問い合わせ」という同じ悩みを持っていて、①の機能をほぼそのまま使える。

### ⑧ 導入支援・研修（デジタル化の伴走）
- 中身: 公式LINEの開設、リッチメニューづくり、役員向けの使い方講座、高齢の住民向けの登録会。
- 形: 1回いくらの導入費。区の「デジタル支援」の委託として受けられることもある。

## 2. NAVITIME などがあるのに、公式LINEに入れる意味はあるか

**ある。別のビジネスになりうる。** NAVITIME やジョルダンは「誰でも・どこでも」の**検索**で、こちらは「この地域の人の**窓口**」。

| | 乗換案内（NAVITIME など） | 自治会の公式LINE |
|---|---|---|
| 開くきっかけ | 自分で調べるとき | 毎日のお知らせ・回覧板と同じ場所。メニューのボタン1つ |
| 中身 | 全国のすべてのバス停 | 地域で使うバス停だけ。保存した「行き」「帰り」がすぐ出る |
| 地域の事情 | 載らない | 自治会が補足できる（運休・工事・お祭りの迂回・特別ダイヤ） |
| 誰が使っているか | わからない | 名簿とつながる（地域ごとの利用、高齢の方への配慮） |
| ほかの機能 | なし | 回覧板・問い合わせ・防災・ごみの日とまとめて使える |

バス時刻表だけで勝負すると乗換案内に勝てない。**「地域の窓口」の中の1機能**として価値が出る。

**注意（事業にするなら必ず）**: いまは京急バスの公式時刻表（NAVITIME のページ）を読み取って使っている。
自分の自治会で使う分にはともかく、**お金をもらって他の自治会にも出すなら、データの出どころと利用条件を確かめる**必要がある。
- 候補: 交通事業者が公開している標準的な時刻表データ（GTFS-JP。公共交通オープンデータセンターなど）。京急バスが公開しているか、利用条件はどうかを確認する。
- 公開されていなければ、京急バスや区に「住民向けの案内に使いたい」と相談する。地域の利用データ（⑤）を返す形にすれば、協力が得やすい。

## 3. 複数の自治会に入れても、管理・保守コストを最小にする案

### ① 1つの仕組みを全部の自治会で使う（マルチテナント）
- 自治会ごとにコピーを作らない。Edge Function は1本、データベースも1つにする。行ごとに「どの自治会のものか」（`organization_id`）を持たせる。
- LINE の Webhook は、公式LINEアカウントごとに URL を分けるか、届いた通知の `destination`（どのアカウント宛か）で見分ける。
- 直す・足すのは1か所だけで、全部の自治会に同時に届く。自治会が増えても、デプロイするのは1つだけで済む。

### ② GAS をやめて Supabase に集める
- GAS は自治会ごとにスプレッドシートとコードのコピーができやすい。コピーが増えるほど、直す場所も増える。
- 名簿・お問い合わせ・バス設定を Supabase に移す（バスは移行済み）。
- スプレッドシートは「見る・書き出す」用途だけにする（必要なら毎日写す）。

### ③ 自治会ごとの違いは「設定」にして、管理画面で各自治会が自分で変える
- 違う点は、自治会の名前、公式LINEの鍵、使うバス停、問い合わせの種類と担当者のメール、リッチメニュー、使う機能の ON/OFF など。
- これらはコードではなく設定の表に持たせ、ポータルの管理画面で各自治会の担当者が変えられるようにする。
- 自分がやるのは「新しい自治会を1行足す」だけにする。
- **いまコードに直接書いてあるもの**も設定に出す: 行き先の名前（「金沢文庫駅 行き」「野村住宅センター 行き」）、停留所選びから外すバス停（関ヶ谷・終点・準備中の夏山坂上）、方面の色。
  これを「自治会の設定表」に移せば、夏山自治会を足すときもコードを変えずに済む。
- バス停の選択・色・案内文などを管理画面で変えられるようにして、「シートを直してください」と頼まれる仕事をなくす。

### ④ 作り込みをしない（標準パッケージ＋機能の ON/OFF）
- 自治会ごとの特注は受けない。要望は「全員に役立つなら標準機能として足す」「そうでなければ断る」の2択にする。
- 文言・メニュー・案内文はテンプレートを用意して、各自治会は選ぶだけにする。

### ⑤ データの更新と見張りを自動にする
- 時刻表は公式のデータから自動で更新する。違いが出たら自動で知らせる（今回作った毎週のチェックの形）。祝日も自動で更新する。
- Edge Function の失敗や、LINE の送信失敗は自動でメールや LINE に知らせる。住民より先に自分が気づけるようにする。
- 表示が変わっていないかの自動試験（今の `parity.mjs` や `send.mjs` の形）を、変更のたびに流す。
- **見張りは1つにまとめる**: エラーや同期の失敗は、全自治会の分を1通のメールにまとめて受け取る。1か所を直せば全員が直る形にしておけば、保守の手間は自治会の数にほぼ比例しない。

### ⑥ 時刻表・祝日・特別ダイヤは全自治会で共有する
- 京急バスの「路線・停留所・時刻」は、自治会ごとではなく**共通の1つの表**で持つ。各自治会は「うちが使うバス停と行き先」を選ぶだけにする。
  - 夏山坂上のように、隣の自治会のバス停でも同じ路線なら、表は1つで足りる。
- 時刻改正の取り込み（今の `BusImportTimetable` ／ `refreshBusTimetableFromNavitime`）と、改正の見張り（`BusScheduleChecker`）は、1回動かせば全自治会の分が済む。保守がいちばん楽になるところ。
- 祝日の表も全員で共通（内閣府の一覧から自動）。特別ダイヤ（年末年始など）は**路線ごとに1つ**持てば足りる。

### ⑦ 自治会ごとにデータを分ける（個人情報の説明責任）
- **LINE のユーザーIDは、公式アカウント（プロバイダー）ごとに別のもの**になる。同じ人でも、関ヶ谷の公式LINEと夏山の公式LINEでは別のIDになる。
  そのため、各人の設定や名簿は、必ず「どの自治会（どの公式アカウント）のものか」と組にして持つ。
- 名簿・バス設定・問い合わせなどの表には「どの自治会のデータか」の列を足す。ほかの自治会のデータが混ざらない・見えないようにする（行ごとの保護 RLS）。
- 「どの自治会の、誰が、何を見られるか」を住民に説明できる形にしておく。個人情報を預かる以上、説明責任の面で重要。

### ⑧ 問い合わせの一次対応は各自治会、自分は二次対応だけ
- 住民からの問い合わせは、各自治会の担当者が受ける（お問い合わせ機能の担当者の設定）。
- よくある質問は案内文・FAQ にして、LINE の中で自動で答える。
- 自分に来るのは「仕組みの不具合」だけにする。不具合の報告にも同じ問い合わせ機能を使う。

### ⑨ 新しい自治会の導入を手順書と自動化で「作業30分」にする
- 公式LINEの開設手順書（画面の写真つき）を用意する。
- 鍵を管理画面に貼るだけで、Webhook の設定・リッチメニュー・時刻表の取り込みまで自動で進むようにする。
- 最初の自治会（隣の自治会）で手順を作り、2つ目からはそれをなぞるだけにする。

### ⑩ 費用の形で保守を支える
- 保守は「月額いくら（自治会の規模で段階）」で受ける。無償で引き受けると、保守が自分の持ち出しになる。
- 共同事務局（事業②）を作るなら、日々の運用（配信・名簿の更新・問い合わせ）はそこで担当し、自分は仕組みの改善に集中する。
- 費用の目安:
  - Supabase と LINE（返信は無料、一斉送信は通数で費用）は、小さい自治会ならほぼ無料枠で収まる。
  - 自治会が増えたら、使った分を自治会ごとに按分する。

## 4. お金の取り方（マネタイズ）

前提: 自治会のお金は会費で、使い道は年1回の総会で決まる。役員は毎年替わり、ボランティアの感覚が強い。
**「いくら払えるか」より「何が浮くか・誰が払うか」**で考える。

### お金を払う人と取り方
| 取り方 | 払う人 | 目安の考え方 | 向き・不向き |
|---|---|---|---|
| A. 月額の利用料 | 各自治会 | 世帯数で段階。回覧板の印刷・配布の手間と費用が減る分より安く | 薄く広く。1自治会あたりは小さい |
| B. 導入費 | 各自治会 | 公式LINEの開設・名簿の移行・役員向け講座・住民の登録会をまとめて | 最初の1回。手間に見合う額に |
| C. 事務局代行（裏方業務の共同化） | 各自治会（数自治会で分担） | 名簿・会費・回覧板づくり・問い合わせ一次対応などを業務委託で | **いちばん大きい**。手間（人）がかかる分、仕組みで減らせるほど利益になる |
| D. 連合町内会・区とまとめて契約 | 連合町内会・区役所 | 地区まとめて導入、委託事業・補助金（制度名と条件は要確認） | 1回の契約で何自治会も入る。**売り込みの手間がいちばん少ない** |
| E. 地域の店の告知枠・協賛 | 地域の店・事業者 | 月いくらの掲載。自治会に一部を戻す | 自治会の負担を下げる補助の収入 |
| F. 交通事業者・区への協力 | 交通事業者・区 | 利用の集計・ダイヤ改正の周知の代行 | 先の話。データがたまってから |

### おすすめの順番
1. **夏山自治会は「一緒に作る相手」として、無料か安い試験価格**で始める。代わりに、使った感想・改善の協力・ほかの自治会への紹介をお願いする。
   ここで「導入の手順（30分）」と「何が浮いたか」（回覧板の印刷・配布・問い合わせ対応の時間など）の数字をそろえる。
2. その数字を持って、**連合町内会（地区）にまとめて提案**する（D）。自治会を1つずつ回るより、売り込みの手間が圧倒的に少ない。
3. 裏方業務の共同化（C）は、関ヶ谷・夏山の2つで形を作ってから値段を決める。収入の柱はここになりやすい。
4. A（月額）は保守の費用をまかなう土台。安く、ただし無料にはしない（無料だと保守が自分の持ち出しになる）。

### 費用のほう
- 仕組みを全自治会で1つにすれば（3 の①⑥）、自治会が1つ増えても費用はほぼ増えない（Supabase は有料プランでも月数千円程度から）。
- LINE の公式アカウントは各自治会のもので、一斉送信の料金はその自治会がLINEに払う（返信は無料）。
- 増えるのは**人の手間**（問い合わせ・導入・事務局代行）。だから「1自治会あたりの手間」を測って値段に反映する。

### 気をつけること
- 予算は総会で決まるので、提案は総会の前（年度の切り替わり前）に。
- 役員が替わっても続くよう、契約は「自治会」と結び、担当者が替わっても引き継げる形に。
- 「お金を取るなら中立か」と見られやすい。名簿などの個人情報は売らない・広告に使わないことを最初に約束する。
- 時刻表のデータを有料サービスで使う場合の利用条件（2 の注意）。

## 5. 使える補助金・制度（2026-10-12 調べ）

金額や条件は年度で変わる。申請・提案の前に必ず窓口で確認する。

### いちばん大事: 横浜市「自治会町内会DX応援事業」の連携協定事業者になる
- 横浜市は、自治会町内会向けのデジタルツールを提供する事業者・NPO と**連携協定**を結んでいる（令和6年度に15者、その後16者目。タウンニュース社・小田急電鉄など。
  アプリは「デジ町」「いちのいち」「結ネット」「My自治会」など）。
- **区の ICT 補助金は、この協定事業者のサービスだけが対象**になっている（緑区）。協定事業者でないと、自治会が補助金を使って導入できない。
- 提案の受付: 横浜市の「共創フロント」テーマ型 No.207、**随時募集**。ヒアリングと書類審査のうえ選定・公開される。
- 条件:
  - 自治会町内会や市と協働できる事業者・NPO 法人（業種・規模は問わない）であること。
  - 概要資料を市のページで公開することに同意すること。
  - 個人情報保護・セキュリティ対策を確認できること。
- 窓口: 市民局地域支援部地域活動推進課（045-671-2317、sh-jichikai@city.yokohama.lg.jp）。
- やること:
  - 提案者になる形（個人事業か法人か NPO か）を決める。
  - 個人情報の扱い（`docs/セキュリティ-RLS.md`・事業化の構想 3⑦）を説明できる資料を作る。
  - 関ヶ谷・夏山での実績をそろえて提案する。

### 区の ICT 補助金（自治会が導入費・利用料に使える）

- 総務省「地域社会DX推進パッケージ事業」（情報通信技術利活用事業費補助金）: 補助率 1/2、**下限500万円**。通信の設備整備などが中心で、地方公共団体・地域の企業・団体向け。自治会の LINE 運用には大きすぎる。

### 横浜市の外へ広げるとき
- ほかの市にも同じような補助がある。例: 奈良県生駒市「地域コミュニティICT活用事業補助金」は電子回覧板などのアプリの導入費・利用料が対象、1/2・上限25万円。

### お金の取り方への影響

- 導入費（B）は区の ICT 補助（9/10・上限10万円）に収まる額にすると、自治会の負担がほぼゼロで始められる。

## 6. 自治会の外：「LINEの裏で動くシステム」はどこが美味しいか（2026-10-12 の相談）

問い: LINE で連絡をとりまくっている組織・小さめの事務所・グループ・水商売などの裏で動く特製システムも作れそう。どこがマーケット的に美味しいか、ニーズは見えるか。

**結論（仮説）**: 狙い目は「**メンバーが決まっていて、LINE で毎日連絡しているのに、名簿・出欠・問い合わせ・お金を手作業で回している小さな組織**」。
手元の部品（名簿と登録フォーム・人による出し分け・問い合わせ受付と再通知・定型情報の自動返事・配信）がそのまま効く。
反対に、不特定のお客を集める店舗の集客は、既存の大手ツールがひしめいていて勝ちにくい。

### 見立て（調べる前の仮説。○◎は「自分の部品が効くか」「払う力」「競合の少なさ」「売りやすさ」を合わせた感触）
| 市場 | LINE でやっていること | 困りごと（ニーズ） | 部品の効き | 払う力 | 競合 | 見立て |
|---|---|---|---|---|---|---|
| 習い事教室・塾・スポーツクラブ・サークル | 保護者・会員との連絡、出欠、振替 | 欠席連絡の取りこぼし、月謝の集金・督促、名簿 | ◎ 名簿・出し分け・問い合わせ | ○ 月数千円 | 中（大手は塾向け中心。小さい教室は空白） | **◎ 本命** |
| マンション管理組合・小規模の賃貸管理・大家 | 入居者からの修理依頼・問い合わせ、お知らせ | 依頼の見逃し、誰が対応したか分からない | ◎ 問い合わせ受付・担当メール・再通知そのもの | ◎ 管理費から出せる | 中 | **◎ 本命**（自治会と同じ形） |
| 工務店・職人・小さい建設 | 現場の写真・日報・職人の手配をグループで | 写真と連絡が流れて探せない、手配漏れ | △ 写真の整理・日報は新しく作る | ◎ | 中（大手ツールは高く重い） | ○ 有望だが作るものが多い |
| 士業・小さな事務所（税理士・社労士・行政書士） | 顧客との書類のやりとり、期限の連絡 | 書類の回収・期限の督促 | ○ 問い合わせ・配信 | ◎ | 中 | ○ セキュリティの説明が重い |
| 介護・訪問系の事業所 | シフト連絡、家族への報告 | 連絡の手間、記録 | ○ | ○ | 中 | △ 個人情報と制度の縛りが重い |
| 美容室・整体・ネイルなどの予約店 | 予約、クーポン配信 | 集客・リピート | △ | ○ | **多い**（LINE の拡張ツール・予約サービスが多数） | △ 価格競争 |
| ナイトワーク（水商売） | キャストの出勤管理、顧客との連絡・同伴予約 | 出勤・指名・売上の手計算、顧客の引き継ぎ | ○ 名簿・出し分け・配信 | ◎ 高い | 中（専用の顧客管理・POS はある） | △ 下の「注意」 |

### 水商売（ナイトワーク）について
- **払う力は高く、LINE 依存も強い。ニーズは本物**。出勤の確定・指名・顧客の引き継ぎ・売上の集計など、手作業が多い。
- ただし注意が要る:
  - **自治会・行政の路線とぶつかる**: 横浜市の協定事業者の募集要件は、風俗営業を営む団体を除外している。
    提案者自身が対象外でなくても、「自治会・行政のパートナー」という信用と同じ名前で出すと、評判で損をしうる。
    **やるなら別の屋号・別ブランド**で。
  - **LINE の規約**: 業種によっては公式アカウントの認証や広告に制限がある（要確認）。
  - 法令（風営法）、反社チェック、個人情報（顧客の連絡先）の扱いが重い。

### ニーズの見え方・確かめ方（作る前に）
1. **聞く**: 各市場で5〜10人に「LINE で何を手作業でやっているか」「一番面倒なのは何か」「月いくらなら払うか」を聞く。
   教室・管理組合は、自治会の知り合いの中に当事者がいそう。
2. **お金が動いている跡を見る**:
   - クラウドソーシングで「LINE 自動化」「LINE 予約」「LINE 名簿」などの依頼を調べる（件数・予算・業種）。
   - 個人が受ける LINE 構築代行の出品・価格を見る。
3. **競合の値段を見る**: 業種ごとの専用ツールの料金表。そこより安く、または手前（もっと小さい組織）を狙えるか。
4. **作らずに試す**: 自治会の部品（名簿・出し分け・問い合わせ）を設定だけで変えて、1つの教室や管理組合で無料試用してもらう。

### 自治会の事業とのつながり
- 本命の2つ（教室・クラブ／管理組合・大家）は、自治会と同じ「**メンバー型の組織の窓口**」。仕組みを1つにして（3 の①③）、業種ごとに案内文と使う機能を切り替えるだけで出せる。
- ブランドは、自治会・教室・管理組合のような「地域・生活」寄りで1つ。水商売など印象の違う市場は、別ブランドに分ける。

## 7. Jカーブ型（スタートアップ型）の成長を狙えるとしたら（2026-10-12 の相談）

問い: この技術・関連技術を使って、スタートアップのような Jカーブ成長をする商品・サービスができるとしたら、何に可能性があるか。

**前提の見立て**: 自治会向け SaaS だけだと、1団体の予算が小さく、売り込みも1つずつなので、**堅実だが伸びは緩やか**（スモールビジネス型）。
Jカーブにするには、次のどれかが要る。
- **使う人が使う人を連れてくる**（口コミ・紹介・グループ招待）
- **使う人が増えるほど価値が上がる**（データ・ネットワークの効果）
- **1回の契約で大量に入る**（自治体・連合会・大手との提携で一気に配る）

### 手元の技術（強み）
- **紙・PDF から予定・締切・対象者を AI で抜き出す**（回覧板の記事化・カレンダー抽出。抽出ルールと品質試験の仕組みまである）
- **LINE を窓口にして裏で業務を回す**（名簿・人による出し分け・問い合わせと再通知・定型情報の即答・配信）
- **公開データを住民向けに使える形にする**（バス時刻表・祝日・特別ダイヤ・公式との自動突き合わせ）
- **複数の団体で1つの仕組みを使う作り**（Supabase・Edge Function・行ごとの保護）

### 可能性のある案
| 案 | 中身 | Jカーブの理由 | 手元の強み | 危うさ |
|---|---|---|---|---|
| **A. 保護者向け「おたより → LINE カレンダー」AI** | 学校・保育園・習い事のプリントを撮る／PDF を送ると、行事・持ち物・締切・提出物を抜き出して、家族の LINE にカレンダーとリマインドで届く | 困りごとが全国の子育て世帯共通で、**親どうし・夫婦間で口コミと招待が自然に起きる**（B2C で広がる）。学校側の導入を待たずに親だけで使える | 回覧板の予定抽出そのもの。抽出品質の試験の仕組みもある | 学校側の連絡アプリ（配信する側）と競合しうる。個人情報（子どもの名前・学校）の扱い。課金は家族プラン・有料の便利機能 |
| **B. 自治体経由の「地域の窓口」プラットフォーム** | 自治会の公式LINE を束ね、行政の配信・防災・住民の問い合わせを1つの仕組みで。自治体・連合会と契約して、その中の全自治会に一気に配る | **1契約で数百団体**（B2G2C）。束ねた数が増えるほど行政にとっての価値（確実に届く道）が上がる | 自治会での実運用。横浜市の協定事業者の道 | 自治体の予算・調達のスピードが遅い。最初の1自治体を取るまでが長い |

| **D. 郊外住宅地の移動の需要データ** | 住民が保存したバスの行き方・見られた時刻表から、「誰がいつどこへ行きたいか」を集計。コミュニティバス・デマンド交通・ダイヤ改正の判断材料に | 高齢化と路線縮小は全国の郊外の課題で、交通事業者・自治体にお金がある。団体が増えるほどデータが効く | バス時刻表・公式との突き合わせ・保存された行き方（46人・55件から） | データの量が要る。時刻表データの利用条件。個人が特定されない集計の設計 |
| **E. 防災・安否確認のネットワーク** | 災害時に LINE で「無事です」をワンタップ、自治会と自治体の画面に集計。要支援者の確認も | 平時は使わないが、**一度起きると全国で必要とされる**。自治体単位で一気に入る | 名簿と LINE がつながっていること | 平時の利用が少なく、継続課金の理由づけが要る（B の機能の1つとして出すのが現実的） |
| **F. LINE 業務システムを作る人向けの土台（道具を売る）** | ココナラ等で LINE 構築を請け負う個人・小さな制作会社が、名簿・出し分け・問い合わせ・配信を組み合わせて客ごとに出せる、複数の客を1つで扱える土台 | **作る人が客を連れてくる**（作る人1人あたり客が複数）。テンプレートが増えるほど価値が上がる | 自治会で作った部品が、そのまま業種テンプレートになる | 既存の LINE 拡張ツールとの競争。作る人向けのサポートが要る |

### 見立て
- **いちばん Jカーブに近いのは A（保護者向けおたより AI）**。困りごとが大きく広い、親だけで使い始められる、口コミと招待で広がる、そして手元の予定抽出の技術がいちばん効く。
- **B は時間がかかるが、取れれば一気に広がる**。自治会での実績と横浜市の協定がそのまま入口になる。自治会事業（小さく堅実）を続けながら、B を育てる形が自然。
- **C と D は A・B の上に乗るデータの事業**。単体では始めず、A・B で集まるデータの価値として後から出す。
- E は B の機能として、F は自治会・教室・管理組合のテンプレートがそろってから。

### 次に確かめること（作る前に）
- A: 子育て世帯 10〜20人に「プリントで困っていること」「今どうしているか」を聞く。既存の保護者向けアプリ・学校の連絡アプリの機能と料金を調べる。
  手元のプリント（PDF・写真）10枚で、抽出がどこまで当たるかを試す（回覧板と同じ試験の仕組みで）。
- B: 横浜市の協定事業者の提案（`自治会町内会DX 連携協定 提案書`）を出し、自治体側が「束ねること」にどれだけ価値を感じるかを聞く。
- 全体: 1人で回すなら、**A（伸びる種）と自治会事業（堅実な土台）を並べて持つ**。B は自治会事業の延長で育てる。

### 注意
- **自治会は政治的中立が求められる**。関ヶ谷自治会・夏山自治会の名前で候補者や構想を支持する動きはしない。やるのは個人（事業者）として。
- **選挙期間中（10/18 まで）は選対に近づかない**。特定候補の支持に見える発信（候補者名を掲げた応援、構想の宣伝）は公選法上の選挙運動と受け取られうる。中身の議論（構想に何が足りないか）は問題ないが、候補者名の扱いは慎重に。
- 選挙後の連絡先は要調査。「地域社会圏研究所」名義の講演（2024 岡山）は現地の設計事務所（koto architecture lab）が主催していたもので、山本氏本人の窓口は山本理顕設計工場か神奈川大学になる見込み。
