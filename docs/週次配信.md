# 週次配信（今週のお知らせ）の仕組み

公式LINEで毎週流す「今週のお知らせ」を、公開中の予定カードとレポートから自動で組み立てる。
目的は「毎週の文面と画像をこちらで用意して、配信担当がコピーして貼るだけにする」こと。
AI は使わず決まったルールで組むので、費用ゼロ・毎回同じ品質で回る。送信自体は LINE 公式アカウントで手動。

- 画面: 管理画面 `/admin?mode=weekly`（「週次配信」タブ）… `apps/circulars/src/components/admin/WeeklyDigest.tsx`
- データ: `event_cards`（公開済みの号に紐づくもの）と「関ヶ谷レポート」枠の公開記事

## 配信のタイミングは「開催日」ではなく「行動が必要な日」で決める

| 種別 | 住民に必要な行動 | 配信すべき時期 |
|---|---|---|
| open（当日参加OK）/ recurring / 種別なし | 当日行く | 開催の週 |
| reserve（要予約） | 申し込む | 締切の1〜2週間前（= 開催の2〜3週間前） |

要予約のイベントを開催日基準で載せると、案内した時点で締切が過ぎていることが多い。
そこで予定カードに **申込締切（apply_deadline）** を属性として持ち、締切基準で拾う。

## 構成と件数上限（情報量を増やさない）

| セクション | 条件 | 上限 |
|---|---|---|
| ⭐ 今週の一押し | ⭐配信候補（weekly_topic）のうち開催が近いもの | 1 |
| 📰 新しいレポート | 直近14日に公開した関ヶ谷レポート（個別URL付き） | 2 |
| ⏰ 締切間近 | 要予約で締切が3日以内 | 制限なし（通常0〜2） |
| 📅 今週の予定 | 要予約以外で、配信日から7日間（配信日を含む。月曜配信なら日曜まで）に開催 | 6 |
| 📝 申込受付中 | 要予約（または締切のあるもの）で締切が14日以内（締切順） | 4 |

- 見出しは「【関ヶ谷自治会 今週のお知らせ】9/21(月)〜9/27(日)」（2026-09-21 に「関ヶ谷」→「関ヶ谷自治会」に変更）。画像の帯も同じ。
- 空のセクションは出さない。文面は 600 文字を目安に、超えたら画面に注意が出る。
- 対象者・参加費（`target_audience` / `fee`）は ⭐一押し と 📝申込受付中／⏰締切間近 の行にだけ「（65歳以上・無料）」の形で添える。📅今週の予定には付けない（文面を長くしないため）。
- 場所は 📅今週の予定・📝申込受付中・⏰締切間近 のすべての行に「（西金沢地域ケアプラザ 多目的ホール）」の形で添える（2026-09-21から申込系にも）。場所は施設名から書く運用（`docs/カレンダー抽出ルール.md`）。
- 締切が未入力の要予約は「開催7日前」を仮の締切にし、文面に「頃」を付ける。

### ⭐一押しの構成（2026-09-21 更新）

```
⭐ 今週の一押し
9/27(日) 13:30〜 会員向け報告会
公式LINEの正式運用開始のご報告と意見交換会。LINEをまだ使っていない方も歓迎です。   ← 紹介文（description）
西金沢コミュニティハウス 多目的室 / 主催: 関ヶ谷自治会（対象・費用）
▶ チラシを見る: https://…/xxx.pdf                                              ← 直リンク
```

- **紹介文** `event_cards.description`（1〜2文・60字程度）。抽出時に AI が内容説明から作る。**週次配信の画面に一押しの紹介文の入力欄があり、その場で書いて保存できる**（予定カードに保存されるので次回以降も残る）。抽出ダイアログと予定カードの編集でも直せる。
- **リンク先** は住民がすぐ詳細を見られるよう、間に画面を挟まず直接つなぐ。優先順:
  1. 由来PDF（`source_pdf_url`）があれば **PDF に直接**（「▶ チラシを見る」）
  2. リンク記事があれば **記事の個別ページ `/?article=<記事ID>`**（「▶ 記事を読む」）
  3. どちらも無ければ **予定の個別ページ `/?event=<予定ID>`**（「▶ 詳しく」。予定の内容＋出典PDF＋記事を1ページで表示）。このページは「チラシも記事も無い一押し」の受け皿としてだけ使う（Flex カードの「予定の詳細」ボタンは 2026-09-21 に廃止）
- 文面のURLは **TinyURL で短縮**する（`https://tinyurl.com/xxxx`）。チラシPDFの直リンクは Supabase Storage のURLで130文字前後あり、文面が600文字の目安を超えやすいため。キー不要・ブラウザから直接取得。取得できないときは元のURLのまま。
- 同じURLをリッチメッセージ（画像）のタップ先にも設定する。画面に「一押しのリンク先」として表示される。

## 配信画像（1040×1040）の種類

画面の「配信画像」で4種類から選ぶ。既定は「一押しチラシ」。

| 種類 | 内容 | 向くとき |
|---|---|---|
| 一押しチラシ（既定） | 一押しの出典PDF 1ページ目をそのまま画像化し、上に「⭐今週の一押し」帯、下に日時・タイトル（最大2行）・場所 | チラシがあるとき。いちばん目を引く |
| 一押しのみ（文字） | 一押し1件を大きな文字で（日時・タイトル・場所・紹介文） | チラシが無いとき（自動でこれに切り替わる） |
| チラシ＋今週の予定 | 左にチラシ、右に日時・タイトル・紹介文、下に今週の予定・申込を最大4行 | 1枚で今週全体も伝えたいとき |
| 文字一覧（従来） | 一押し＋今週の予定・申込を文字だけで一覧 | 従来どおりにしたいとき |

- チラシは一押しの由来PDF（`source_pdf_url`）を使う。無ければ出典号の先頭PDFで代用し、画面にその旨を出す（内容が合わなければ他の種類を選ぶ）。
- PDF の画像化はブラウザ内で pdf.js（回覧板一覧のサムネイルと同じ設定）で行う。API 費用はかからない。

## LINE に送る（Flex カルーセル・2026-09-21 追加）

管理画面の「LINE に送る（カード形式）」から、Messaging API で直接配信できる。コピー＆貼り付けの手順は不要になる。

**1回の配信の中身（吹き出し3つ・通数は1通）**

1. テキスト: 見出し＋「⭐今週の一押しは …」＋「下のカードをスワイプして…」（画面で編集可）
2. ⭐ 今週の一押し（Flex・1枚だけ、最大2件を縦に）… 見出し帯＋（件ごとに）チラシ画像（正方形・切り出し位置は人が決める）＋タイトル・日時・場所・紹介文＋「詳しく見る」（行き先は指定があればそれ、無ければ チラシPDF → 記事 → 予定ページ。一押しはチラシとは限らないので言葉は固定）
3. Flex カルーセル（該当の無いカードは出ない。1枚だけならカルーセルにしない）
   - 📅 今週の予定 … 行ごとにタップで詳細（⏰締切間近があれば先頭）
   - 📝 申込受付中 … タイトル・開催日・締切・場所。行ごとにタップ
   - 📰 新しいレポート … 1本ずつ（扉写真＋タイトル＋「レポートを読む」）

カードの決まり（2026-09-21）:
- **文字は全体に一段階大きめ**（見出し lg／本文・日時・「詳しく ›」md／補足・場所 sm、ボタン高さ md）。Flex の文字は LINE の文字サイズ設定（特大など）に連動せず固定なので、高齢の読み手に合わせてカード側で大きくしている。
- 一押しカードにも見出し帯（⭐ 今週の一押し・琥珀色 #b45309）。帯 → チラシ画像 → 本文 → ボタンの順。
- 「今週の予定」の下のボタンは **「ほかの予定も見る」**（行は今週の分、ボタンは来週以降も含めた一覧＝回覧板サイト）。
- 「申込受付中」には下のボタンを置かない（申込が複数・別PDFのとき行き先が1つに決められないため）。各行がそれぞれのチラシ（または記事）へ飛ぶ。
- 今週の予定・申込受付中の行は共通レイアウト（1行目: 日時または締切 ／ 2行目: タイトル ／ 補足・場所 ／ 右端: **「詳しく ›」**を固定幅64pxの枠に）。日付を左の列にすると実機（本文幅260px前後）で「9/25(金)」の閉じカッコや「〜」が折れるため、日時は横幅いっぱいの1行にする（2026-09-21 実機確認で修正）。「詳しく ›」は本文と同じ大きさの太字・濃いグレー（#555555）。青は使わない（カードの色は見出し帯だけ。色が多いと迷う）。両カードの見出し下に「「詳しく ›」をタップすると案内が開きます」。
- **チラシも記事も無い予定**（行事予定表から拾っただけの合同会議など）は、「詳しく ›」を出さずタップなしにする（予定ページには飛ばさない）。

配色は「役割別＝リンク先の色」: 今週の予定は回覧板サイトのブルー（#2563eb）、申込受付中はグリーン（#2f6f4e、行動が必要なもの）、レポートはレポートの赤（#c0392b）。一押しは見出し帯もボタンも琥珀色（#b45309）で揃える。締切の文字は赤（警告色として埋もれないように他を赤にしない）。

一押しを別の吹き出しにしているのは、LINE のカルーセルが「全カードの高さを一番高いカードに揃える」仕様で、背の高い一押しと同じカルーセルに入れると他のカードに大きな空白ができるため（2026-09-21）。

**ボタン**

| ボタン | 動き |
|---|---|
| 形式チェック | 送らずに LINE 側で JSON を検証（`validate/broadcast`） |
| Flex JSON をコピー | LINE Developers の Flex Message Simulator に貼って本物の描画を確認する用 |
| テスト送信（自分に） | `LINE_TEST_USER_ID` にだけ push。見た目確認用（1通消費） |
| 全員に配信 | 確認ダイアログの後、友だち全員に broadcast。履歴に残り、同じ配信日の二重配信には警告が出る |

**仕組み**

- 送信は Edge Function `line-broadcast`（`supabase/functions/line-broadcast/`）経由。チャネルアクセストークンはサーバー側のシークレットにだけ置く。app-login のアプリトークン（`x-app-token`）で保護。
- チラシ画像は送信時に `newsletter-images/weekly/<配信日>-flyer.jpg` にアップロードし、その https URL を Flex のヒーロー画像に使う（同じ配信日は上書き）。カルーセルは全カードの高さが揃うため、チラシは**上部を正方形に切り出したもの**を載せる（縦長のままだと他のカードに大きな空白ができる）。全体は「チラシを見る」で開く。
- 履歴は `weekly_digest_sends`（`sql/migrations/2026-09-21-weekly-digest-sends.sql`）。
- コード: 組み立て `weeklyFlex.ts`、プレビュー `FlexPreview.tsx`、共通ロジック `weeklyDigestCore.ts`、クライアント `packages/shared/services/data/lineBroadcastService.ts`。

**初回セットアップ（1回だけ）**

1. LINE Developers（https://developers.line.biz/）で、公式アカウントに紐づく **Messaging API チャネル** を有効にし、「チャネルアクセストークン（長期）」を発行する。
2. 同じ画面の「あなたのユーザーID」（Uで始まる）を控える（テスト送信先）。
3. Supabase ダッシュボード（sekigaya-portal）→ Edge Functions → Secrets に追加:
   - `LINE_CHANNEL_ACCESS_TOKEN` = 1のトークン
   - `LINE_TEST_USER_ID` = 2のユーザーID
   - （`APP_TOKEN_SECRET` は app-login と共通で設定済み）
4. Edge Function をデプロイ: `supabase functions deploy line-broadcast --project-ref iplcopuwwzbtwoakqifh --no-verify-jwt`（または MCP の deploy_edge_function）。
5. SQL Editor で `sql/migrations/2026-09-21-weekly-digest-sends.sql` を実行（履歴テーブル。無くても送信はできる）。
6. 管理画面で「形式チェック」→「テスト送信」で確認。

**注意**

- Messaging API の配信も公式アカウントの通数に含まれる（無料プランは月200通。友だち数×配信回数）。
- 画像・リンクは https 必須。ローカル（localhost）からは形式チェックがリンクのURLで失敗するので、本番かプレビュー環境で試す。
- チャネルアクセストークンを再発行したら Secrets も更新する。

## ⭐一押しを人が選ぶ（2026-09-21、09-22 に2件まで・リンク先・切り出し位置を追加）

週次配信画面の「⭐ 今週の一押し」でチェックして決める（**最大2件**、チェックした順に並ぶ）。
- **自動**（既定）: ⭐配信候補のうち開催が直近（2週間以内優先）の**1件**。「自動に戻す」でいつでも戻せる。
- **今週は一押しなし**: 一押しカードと文面の⭐段落を出さない。配信はテキスト→カード一覧の2吹き出し。
- **任意の予定**: ⭐候補、または4週間以内のその他の予定から選ぶ（⭐が無くても可）。
- 一押しから外れた予定は、今週の範囲内なら「今週の予定」に普通の行として載る。選択は保存せず、配信日を変えると自動に戻る。
- 「載せる予定」一覧で一押しのチェックを外すのは「その予定ごと今週の配信から外す」動き。一押しだけ無しにしたいときは「今週は一押しなし」。

一押しごとに次を設定できる（一押しの枠の中）。
- **紹介文**（予定カードに保存。次回以降も使われる）
- **「詳しく見る」のリンク先**: チラシ（PDF）／記事／予定ページ から選ぶ（無いものは出ない）。指定しなければ チラシPDF → 記事 → 予定ページ の順。文面の「▶」とカードのボタン・画像のタップ先に使う。この週だけの指定（保存しない）。
- **カード画像の切り出し**: カードに載せる正方形を、プレビューのドラッグ（位置）とスライダー／ホイール（拡大 ×1〜×3）で決める（`CropEditor.tsx`、計算は `heroCrop.ts`）。「切り出しを保存」で予定カード（`event_cards.hero_crop` = `{x,y,scale}`、`sql/migrations/2026-09-22-event-cards-hero-crop-json.sql`。旧 `hero_crop_y` も残す）に残る。
- **画像の元**は `topicImageSource`: 由来PDF（チラシ）の1ページ目 → **リンク記事の写真**（扉写真か画像添付の先頭。記事由来の予定用）→ 出典号の先頭PDF（代用）の順。`getPublishedEventCards` はこのために記事の `thumbnail_url` と `attachments` を一緒に取る。

一押しカード（Flex）は**1枚のカードに最大2件を縦に並べる**（見出し帯 → [画像・タイトル・日時・場所・紹介文・「詳しく見る」] × 件数、区切り線入り）。画像は hero ではなく本文の image 部品。配信画像（1040×1040）は先頭の一押しだけで描く。

## 載せたくない予定を外す（人のオプトアウト・2026-09-21）

アルゴリズムが拾った予定を人が外す手段は2段階ある。

| 手段 | 効き方 | 場所 |
|---|---|---|
| **この週だけ外す** | 「載せる予定」一覧のチェックを外す。文面・画像・カードのすべてから消える。保存しないので来週また拾われる | 週次配信画面 |
| **今後も載せない** | 予定カードの `digest_exclude` を立てる。以後の週次配信に出ない。カレンダー（今後のイベント）には載る | 週次配信画面の「🚫 今後も載せない」／抽出ダイアログの「🚫 配信に載せない」／号の予定カード編集のチェック |

- 抽出時に AI が目安を付ける（`DIGEST_EXCLUDE_RULE`: 役員会・合同会議・委員会・監査・選考など一般住民の参加を想定しないもの）。判定は揺れるので人の確認が本線。
- マイグレーション: `sql/migrations/2026-09-21-event-cards-digest-exclude.sql`（適用済み）。

## 運用手順（毎週）

1. 管理画面「週次配信」タブを開く（配信日は既定で当日）。
2. 内訳（⭐1件・📅5件…）と「載せる予定」一覧を確認。載せたくない予定はチェックを外す（役員向け会議などは「今後も載せない」）。
3. 「文面をコピー」→ LINE 公式アカウントのメッセージに貼る。必要なら「PNGを保存」した画像をリッチメッセージに使う。
4. ⭐ の付け外しや締切の修正は、回覧板の「イベント抽出」ダイアログか予定カードの編集で行う。

## データの前提

- 抽出時に `kind` / `weekly_topic` / `apply_deadline` / `target_audience` / `fee` / `description` が付く（`docs/カレンダー抽出ルール.md`）。
- 締切は「イベントの属性」。自治会以外の PDF からは締切だけの独立カードは作らないが、要予約イベントの属性としては拾う。
- 必要なマイグレーション: `sql/migrations/2026-09-07-event-cards-kind-topic.sql`、`2026-09-08-event-cards-deadline.sql`、`2026-09-08-event-cards-audience-fee.sql`、`2026-09-21-event-cards-description.sql`。

## 既存の予定カードを壊さずに追加抽出する（9月号など「記事しか読んでいない号」向け）

抽出ダイアログで再度「イベント抽出」を実行しても、登録済みのイベントは二重登録されない。

- 候補ごとに「同じ日付＋正規化タイトル」で既存カードと突き合わせ、一致すれば「✔ 登録済み → 空欄だけ補完」と表示する。
- 登録ボタンを押すと、一致したものは新規追加せず、既存カードの **空欄だけ**（時間・場所・主催・種別・kind・⭐・申込締切・由来PDF）を候補の値で埋める。
  タイトル・日付・記事リンクなど、人が直した可能性のある項目には触れない。
- 一致しなかったもの（PDFにしか無かったイベント）は新規カードとして追加される。
- 手順: 号を開く →「イベント抽出」→ ソース選択で「記事テキスト」も「添付PDF」も選ぶ → 候補を確認 → 登録。
  記事由来のカードは補完され、PDF由来の新しい予定だけが増える。
