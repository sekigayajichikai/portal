# LINE リッチメニュー（人によって出し分ける）

公式LINEの下に出るメニューを、管理画面の「リッチメニュー」タブから作り、Messaging API で登録・出し分けする。
LINE公式アカウントの管理画面（OA Manager）で作ったメニューとは**別管理**（APIからは読めない）。優先順位は
**個別に紐づけたメニュー ＞ APIの「全員の既定」 ＞ OA Manager のメニュー**。

- 画面: `/admin?mode=richmenu` … `apps/circulars/src/components/admin/RichMenuManager.tsx`
- 画像とタップ領域の生成: `richMenuImage.ts`（2500×1686、テンプレート `grid3x2` / `promo`、タブ帯15%）
- API: Edge Function `supabase/functions/line-richmenu/`（`op` で操作を指定）。クライアントは `packages/shared/services/data/lineRichMenuService.ts`
- 定義の保存: `line_rich_menus`（`sql/migrations/2026-09-21-line-rich-menus.sql`）。画像は Storage `newsletter-images/richmenu/`

## 操作の流れ

1. 上の4タブ（**通常メニュー／登録促進／通常メニュー（登録前）／防災訓練タブ**）から役割を選ぶ。役割ごとに保存メニューは1つで、初回はサンプルが入っている。タブのバッジで状態（未作成／保存済み／LINE登録済み／★既定）が分かる。役割は `definition.role` で持つ。
2. 文言・行き先・色・タブを直す。画像は自動生成（手持ちの画像に差し替えも可。1MB以内）。**保存済みのメニューを開いたときは Storage に保存した画像を表示・使用する**（手持ち画像 ＞ 保存した画像 ＞ 自動生成の順）。タイルや色を直したら「自動生成に切り替える」で作り直し、次の「保存」で画像も置き換わる。
3. 「保存」（この画面の保存＋画像を Storage へ）→「LINE に登録」（作成＋画像アップロード＋エイリアス）。
4. 「自分だけに反映」で実機確認（`LINE_TEST_USER_ID`）。トーク画面を開き直すと見える。数人で確認したいときは「管理者だけに反映」（Secrets の `LINE_ADMIN_USER_IDS` にカンマ区切りで入れたDX委員などのユーザーID）。「管理者の反映を解除」で既定に戻る。
5. 「全員の既定にする」か、「特定の人にだけ」にユーザーIDを貼って紐づける。
6. やめるときは「自分の反映を解除」「紐づけを解除」「既定を解除」「LINE から削除」。

## 決まったエイリアス（名簿GASと共有）

| エイリアス | メニュー | 誰に |
|---|---|---|
| `menu-touroku` | 登録促進（1枚目） | 未登録の人（名簿GASが毎晩紐づけ。友だち追加時も即時） |
| `menu-normal-pre` | 通常メニュー（登録前）（2枚目） | 同上。タブで切り替えた人 |
| `menu-normal` | 通常メニュー（タブ付き、1枚目） | 地区長・班長・代理（名簿GASが毎晩紐づけ。本登録時も即時） |
| `menu-bosai` | 防災訓練（2枚目） | 同上。タブで切り替えた人 |

- 登録し直すと richMenuId が変わる（LINE は登録済みメニューを書き換えられないため作り直す）。外部の GAS が ID を持たなくて済むよう、「LINE に登録」のたびに自分のエイリアスを新しい ID に付け替える（タブ付きは `tabs.aliases[position]`、タブ無しの登録促進は `ROLE_ALIASES`）。
- エイリアス名は `richMenuImage.ts` の `TAB_PAIRS` と、Jichikai_Line の `gas/RichMenuSync.js` の `RICHMENU_ALIASES` で同じにしておく。
- GAS 側（`syncPromoRichMenu`、毎晩）: エイリアス一覧から ID を引き、1人ずつ「今のメニュー」を LINE に聞いて、あるべきペアと違う人だけ `bulk/link`（500人ずつ）／`bulk/unlink` する。タブで切り替えた先にいる人は戻さない。「自分だけに反映」などで付けた別のメニューは触らない。登録時・友だち追加時はその場で1人分を切り替える。
- 作り直すと古いメニューは削除され、それに紐づいていた人は既定（OA Manager）に戻る。次の GAS 同期で新しいメニューに紐づけ直される（急ぐなら GAS エディタで `syncPromoRichMenu` を手動で回す）。

## 登録促進をタブ付きにする初回の手順（2026-10-28）

順番が大事。2枚目を先に作らないと、タブを押しても切り替わらない。

1. 「通常メニュー（登録前）」タブを開く（サンプルは通常メニューと同じ6タイル。行き先URLを通常メニューと同じに直す）→ 保存 → LINE に登録（エイリアス `menu-normal-pre` が付く）。
2. 「登録促進」タブを開き、「上にタブを付ける」をオン（既定で「📝 会員登録｜🏠 通常メニュー」の1枚目）→ 保存 → LINE に登録（`menu-touroku` が新しい ID に付け替わる）。 画像の元が「定義から自動生成」になっていることを確かめる（タブを変えると自動で切り替わる。保存した画像のままだとタブの帯が無い画像が LINE に送られる）。
3. 「自分だけに反映」で、タブを押して行き来できるか確かめる。
4. 古い登録促進に紐づいていた人は既定に戻っているので、名簿GASの `syncPromoRichMenu` を手動で1回回す（翌晩を待ってもよい）。

## タブ切替の仕組み

- 2つのメニューを、それぞれ「上にタブを付ける」をオンにして登録する。タブ1・タブ2の文言とエイリアスIDは両方で同じにし、「このメニューはタブ1／2」だけ変える。オンにしたときの既定は役割で決まる（`defaultTabsFor`）: 通常／防災訓練は「🏠 通常メニュー｜🚨 防災訓練」、登録促進／通常メニュー（登録前）は「📝 会員登録｜🏠 通常メニュー」。
- 登録時に自分のエイリアス（例: 通常＝`menu-normal`）をその richMenuId に向ける。タブ領域は `richmenuswitch` で相手のエイリアスへ切り替える。
- 作り直したときは同じエイリアスに付け替えるので、もう一方のメニューはそのままでよい。

## 制約・注意

- 既定が OA Manager のメニューのとき、API の「既定を読む」は `the richmenu is owned by another channel` を返す。画面では「既定はGUI管理」と表示し、エラーにしない。

- 画像は 2500×1686（または 2500×843）の PNG/JPEG、1MB 以内。自動生成は PNG で収まらなければ JPEG に落とす。
- 一括紐づけは 500 人ずつ（Edge Function 内で分割）。ユーザーIDは `U`＋32桁の16進。
- 管理者のユーザーIDは Supabase の Custom Secrets `LINE_ADMIN_USER_IDS`（例: `Uxxx…,Uyyy…`）。画面には出さない。
- メニュー名 300 文字、バーの文言 14 文字、タップ領域は 20 個まで。
- エイリアスは半角英数と `-` `_`、32 文字まで。
- OA Manager のメニューと衝突しない（APIの既定が優先）。API の既定を「解除」すると OA Manager のメニューに戻る。
- LINE 側に作れるリッチメニューは 1000 個まで。作り直しのたびに古いものは削除する（画面が自動で行う）。
