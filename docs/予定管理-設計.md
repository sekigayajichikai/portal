# 予定管理タブ（予定カードの横断管理）— 設計

状態: **第1段 実装済み** 2026-09-28（設計 2026-09-26。はなさんの「イベント管理するページが必要ですかね？」から）。

決定（2026-09-28）: 手動追加は第2段 ／ 週次配信の紹介文欄は残す ／ 一覧の既定は「今日以降・全号」（下書き・旧版の号はバッジで区別）。

### 実装メモ（第1段）
- 予定タブ: `EventsPanel.tsx`（`/admin?mode=events`）。取得は `getAdminEventCards({ fromDate })`（今日以降＋日付未定。「過去も表示」で全件）。
- 編集ダイアログ: `EventCardEditDialog.tsx`。カードIDを渡すと自分で `getAdminEventCardById` で読み込む（号の画面・週次配信・予定タブの3か所から同じもの）。変更した項目だけ `updateEventCard` に送る。画像の切り出しは「画像を読み込んで切り出しを調整」を押したときだけPDFを描く（重いので）。
- 記事の選択: `ArticleLinkPicker.tsx` ＋ `getArticlesForLinking(newsletterId)`（公開中の号の記事すべて＋この予定の号の記事。この号 → 新しい順）。
- 重複: `eventMatch.ts` の `findDuplicateGroups` と `buildMergeUpdates`（残す側の空欄だけ埋める）。疑う見方は2つ。
  ① **同日＋似た題名**（`isSameEventTitle`）② **同日＋同じ開始時刻＋同じ主催**（題名が全く違っても同じ枠の催しのことがある。
  2026-09-29: 10/19 13:30 ふれあいの会の「YouTube カフェ」＝予定表の枠名 と「歌声喫茶～秋の思い出と懐かしの名曲を歌おう～」＝当日の催し名）。
  まとめたときは、消した側の予定がカレンダーに載っていれば `removeCalendarEventByCard` でそちらからも消す。
- 号の画面: インライン編集をやめ、✏️と「＋ 記事をリンク」でダイアログを開く。別の号の記事へのリンクは号名を添えて表示。
- 週次配信: 一押し枠に「この予定を編集」。紹介文欄と切り出しはそのまま残した。PDFの1ページ目の描画（`renderPdfFirstPage`）は `heroCrop.ts` に移して共有。
- 「＋ 予定を追加」（号に属さない予定）は第2段。

## なぜ必要か

予定カード（`event_cards`）は「号」にぶら下がっていて、編集は電子回覧板タブで号を開いた先でしかできない。
ところが実際の困りごとは、どれも **号をまたぐ** ものだった。

| 困りごと（2026-09-25〜26 に実際に起きた） | いまの対処 | 予定管理タブがあれば |
|---|---|---|
| 9月号の行事予定と10月号で同じ予定が二重登録 | SQL で8件削除 | 一覧で同日の似た題名を並べて警告 → 片方を削除／統合 |
| 10月号のズーラシアに、9月号の詳しい記事（写真付き）を付けたい | 号の画面は同じ号の記事しか選べない → SQL | 記事リンクを「公開中の全号」から号名付きで選ぶ |
| 場所・主催の表記を全体でそろえたい | 会場マスタ＋SQL 一括置換 | 一覧で「マスタに無い表記」を色で示し、その場で直す |
| 配信に載せない／紹介文／画像の切り出しを号に関係なく直したい | 週次配信の画面に編集機能が入り込んでいる | 1つの編集ダイアログに集約し、週次配信からも同じものを開く |

## 位置づけ

- 管理画面に **「予定」タブ**（`/admin?mode=events`）を追加。タブは 電子回覧板／関ヶ谷レポート／週次配信／リッチメニュー／予定／マスタ の6つ。
- **号の画面の予定カード一覧は残す**（抽出直後の確認用）。細かい編集は「予定」タブと同じ編集ダイアログに寄せ、二重実装をやめる。
- **週次配信の画面からは編集機能を減らす**: 紹介文・切り出し・「今後も載せない」は、一押し枠の「この予定を編集」から同じダイアログを開く形に置き換える（配信文の組み立てに集中させる）。ただし紹介文の入力欄はその場で書けた方が速いので、第1段では残し、第2段で判断する。

- 対象は **今日以降** を既定に（「過去も表示」で切替）。全号（下書きの号も含む）。日付順。
- 列: 日付・時間・題名・場所・主催・性質(kind)・種別(category)・⭐・締切・号（状態付き: 下書き／公開）・添付の有無（📎由来PDF／🔗記事）・🚫配信除外。
- 行をクリックで編集ダイアログ。
- **重複の警告**: `eventMatch.ts` の `isSameEvent` で同日・似た題名の組を見つけ、行の下に相手を表示。「見比べる」で2件を横に並べ、「左を残す／右を残す」で削除（残す側の空欄はもう片方の値で埋める＝抽出ダイアログの `buildFillUpdates` と同じ）。
- **場所・主催の色**: 会場マスタ／主催団体マスタに無い表記は薄い黄色。
- 号が下書きのカードはグレーの「下書き」バッジ（公開側には出ていないことが分かる）。

### データ・サービス

- 読み込み: `getEventCardsFrom(fromDate)`（実装済み。号の題名・状態付き）を拡張して、`linked_article` の題名と写真の有無、`source_pdf_url` も返す（`select('*, newsletters(title,status), linked_article:articles!linked_article_id(id,title,thumbnail_url)')`）。
- 記事の候補: `getArticlesForLinking()` … `articles` を `newsletters!inner(status='published')` で絞り、`id, title, newsletter_id, newsletter_title, thumbnail_url` を返す。件数が増えたら題名の部分一致で絞る。
- 更新・削除: 既存の `updateEventCard` / `deleteEventCard`。
- **DB変更なし**（第1段）。

### 既存画面との関係

- 号の画面（`NewsletterList.tsx`）: 予定カードのインライン編集（日付・時間・題名・場所・紹介文・配信除外）を、編集ダイアログを開くボタンに置き換える。「＋ 記事をリンク」の同じ号限定の選択も、ダイアログ側の全号選択に統一。
- 週次配信（`WeeklyDigest.tsx`）: 一押し枠に「この予定を編集」を足し、同じダイアログを開く。保存後は `load()` で読み直し。
- 公開側（カレンダー・週次配信）は変更なし（「公開済みの号のカードだけ」の条件はそのまま）。

## 第2段（あとで）
