# 「自分以外の人も使える」ための改善提案リスト

作成日: 2026-08-29
目的: ITに詳しくない役員・担当者でも、月次の「PDFアップロード → 記事チェック → 担当者確認 → 公開」を一人で回せるようにする。

## 想定ユーザー像

- 自治会の役員・広報担当（毎年交代する可能性あり）
- PCよりスマホ中心の人も多い
- 「Supabase」「トークン」などの技術用語は通じない前提

---

## A. すぐ直せる改善（効果大・作業小）

### A-1. ブラウザ標準ポップアップの全廃 ⭐最優先
現状 `alert()` が80箇所、`confirm()` が20箇所。ブラウザ標準のダイアログは
「sekigayajichikai.vercel.app の内容」という不安を煽る見出しが付き、見た目も操作も分かりにくい。

- 成功通知 → 画面内に緑のトースト通知（数秒で自動で消える）
- 確認 → アプリ内の確認ダイアログ（大きなボタン、何が起きるかを日本語で説明）

### A-2. 技術用語を画面から追放
- 「Supabase」がUI文言に40箇所 →「保存しました」だけでよい
- 「トークン」→「確認用リンク」
- エラーの生メッセージ（`err.message` 直出しが17箇所）→
  「保存できませんでした。電波の良い場所でもう一度お試しください」のように
  **原因より対処法**を伝える日本語に置き換え

### A-3. 呼び方の統一
- Newsletter / 号 / 回覧板 が混在 → 利用者向けは「◯月号」「回覧板」に統一
- 「下書き / 確認待ち / 承認済み / 公開済み」のステータス表現は現状のままで良い

### A-4. ボタンと文字を大きく（スマホ最適化）
- 管理画面をスマホで開いたときの操作性を点検
- 主要ボタン（公開・確認依頼）は大きく色分けし、迷わない配置に

---

## B. 少し作り込む改善（数日規模）

### B-5. 「今月の流れ」ガイド付きホーム
管理画面を開いたら、まず今月やることがステップで見える:

```
① PDFをアップロード ✅ → ② 記事をチェック ✅ → ③ 担当者に確認 ⏳ → ④ 公開
```

どこまで終わっていて次に何をすればいいかが一目で分かる。

### B-6. 確認リンクの共有をワンタップに
- 現状: リンクをコピー → LINEを開いて貼り付け
- 改善: 「LINEで送る」ボタン（LINE共有URL）や、その場でQRコード表示

### B-7. 処理中・保存状態の見える化
- 「保存中…」のくるくる表示、完了時は緑のチェック
- ボタンの二重押し防止（AI抽出中など時間のかかる処理は特に）

### B-8. 削除の安全ネット（ゴミ箱方式）
- 現状は即時完全削除。誤操作で取り返しがつかない
- 「削除 → ゴミ箱へ（30日間は戻せる）」に変更
- ※今回のデータ消失事故の教訓をアプリ自体にも反映

### B-9. 操作履歴
- 「誰がいつ公開したか / 削除したか」を記録して一覧できるように
- 承認フローで作った記録（承認者名・日時）の考え方を他の操作にも広げる

---

## C. 大きめの構想（将来・複数人運用の本丸）

### C-10. 個人アカウント化
- 現状は全員共通の1パスワード（誰の操作か分からない、退任者が出るたび変更が必要）
- 一人ひとりのログインにして役割を分ける:
  - **閲覧のみ** / **編集できる** / **公開できる（責任者）**
- 承認フローと自然につながる（承認者がログインして承認）

### C-11. 自動バックアップ
- Supabase無料プランには自動バックアップがない
- 週1回、データを自動でエクスポートして保管する仕組み（GitHub Actions等）
- PDF原本も必ずストレージに残す運用の徹底

### C-12. 引き継ぎ資料の自動整備
- スクショ付きの操作マニュアルを docs/ に整備
- 役員交代のときに「このページを読めば分かる」状態にする

---

## おすすめの着手順

1. **A-1 + A-2**（ポップアップ廃止と用語の日本語化）— 見た目の分かりやすさが一気に変わる
2. **A-3 + A-4** — 同じ作業のついでに実施できる
3. **B-5**（ガイド付きホーム）— 「誰でも回せる」の核になる
4. **B-8 + C-11**（ゴミ箱・バックアップ）— 安全網。事故の再発防止
5. B-6, B-7, B-9 → C-10（アカウント化）→ C-12
