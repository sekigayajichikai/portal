# マスタ管理（会場・主催団体・発行元）

管理画面の **「マスタ」タブ**（`/admin?mode=masters`）で、予定カードや回覧板で使う名前の一覧を管理する。
2026-09-26 に、それまでヘッダーの小さなボタンから開いていた主催団体・発行元のモーダルを、会場マスターの追加にあわせて専用タブにまとめた（`MastersPanel.tsx`）。

| マスタ | テーブル | 用途 | 使われる場所 |
|---|---|---|---|
| 会場 | `venues` | 予定カードの実施場所（`event_cards.event_location`） | イベント抽出のAIヒント、抽出ダイアログと予定カード編集の場所欄の候補、別名→正式名の自動置き換え |
| 主催団体 | `organizers` | 予定カードの主催（`event_cards.organizer`） | イベント抽出のAIヒント、抽出ダイアログの選択ピッカー |
| 発行元 | `publishers` | 回覧板PDFの発行元（自治会・ケアプラザ・学校など） | 回覧板の作成時のPDFの発行元選択 |

## 会場マスター（2026-09-26）

**目的**: 場所の表記をそろえる。AIの抽出は号ごとに「自治会館1階会議室／自治会館 1F会議室／自治会館1F会議室」のように揺れ、
「施設名＋部屋名」で書く決まり（`LOCATION_RULE`）だけでは止まらなかった。

**構成**
- **正式名** `name`: 施設名＋部屋名（例: 西金沢コミュニティハウス 2階）。施設だけの名前（西金沢コミュニティハウス）も別に持てる。
- **別名** `aliases`: 揺れた表記や略称（コミュニティハウス 2階、コミハ2階 など）。「、」区切りで入力。

**効き方**
1. **抽出時のAIヒント**: 正式名の一覧をプロンプトに渡し、「該当する場所はこの名称をそのまま使う。部屋名まで分かれば部屋名付き、施設名しか分からなければ施設名だけ」と指示する（`buildVenueHint`、`eventExtractionPrompt.ts`。`scripts/schedule-test/prompt.md` にも反映）。
2. **自動の置き換え**: 抽出結果と場所欄の入力確定時に `resolveVenueName` を通す。空白・全角英数・「1F/1階」・ケ/ヶ を吸収して正式名か別名に一致すれば正式名に置き換える。一致しなければ原文のまま（自由入力もできる）。
3. **候補の表示**: 抽出ダイアログと予定カード編集の場所欄に正式名の候補（datalist）が出る。マスターに無い表記のときは抽出ダイアログの欄が薄い黄色になる（そのまま登録もできる）。

**初期データと既存カードの整理**: `sql/migrations/2026-09-26-venues-master.sql`（本番適用済み）。2026-09-26 時点のカードに出ていた14通りの表記から10件の正式名を作り、
別名に一致する既存カードの場所を正式名に置き換えた（自治会館 1F会議室 → 自治会館 1階会議室、コミュニティハウス 2階 → 西金沢コミュニティハウス 2階、2階多目的ホール → 多目的ホール など）。

**運用**
- 新しい会場が出てきたら「マスタ」タブで正式名を登録する。揺れた表記を見つけたら、その正式名の別名に足す（次からは自動で置き換わる）。
- 正式名を変えても既存カードの文字は変わらない（一括で変えたいときは SQL で `UPDATE event_cards SET event_location = ... WHERE event_location = ...`）。
- 削除してもカードの文字は残る。
