# 公式LINEのバス時刻表（名簿GAS）

コードはこのリポジトリではなく、**名簿スプレッドシート（LINE_meibo）の GAS** にある（`BusTimetable.js`、入口は `Main.js` の `doPost`）。
時刻表・各人の設定・特別ダイヤは別のスプレッドシート（`BUS_SHEET_ID`）。

- 「バス」→ 保存した1件目の行き方の時刻表（未保存なら方向選び）。「マイバス」→ 保存した行き方の一覧（最大3つ）。「バス検索」→ 方向選び。
- 平日／土休日は、特別ダイヤシート → 土日 → Google の祝日カレンダー の順で決める。

## 速さ（2026-10-11 測定）

基準と測り方は `問い合わせ.md` の「速さ」と同じ（2秒以内は合格／2〜3秒は要注意／3秒超は遅すぎ）。
偽の返信トークンで測るため、返信失敗→エラー文の送信が1回多く、実際より 0.3〜0.5秒ほど長めに出る。

| 手順 | 対策前 | 対策後（温まった状態） |
|---|---|---|
| 何もしない文（GAS の起動待ちだけ） | 1.2〜2.0秒 | 1.0〜1.3秒 |
| 「バス」（保存した行き方の時刻表） | **3.7〜6.6秒** | 2.0〜2.2秒 |
| 「マイバス」（一覧） | 2.3〜3.7秒 | 1.6〜2.1秒 |
| ダイヤ切替 | 2.2〜3.5秒 | 2.0〜2.7秒 |
| 停留所を選ぶ → 時刻表 | 2.4〜2.8秒 | 2.3〜3.2秒（シートを開かない手順と差がなく、通信のばらつき） |

遅かった理由と対策:
- 各人のバス設定を毎回シートから読んでいた → 人ごとに6時間キャッシュ（保存・削除・名前変更で消す。シートを手で直したときは6時間以内に反映）。
- 祝日かを毎回 Google カレンダーに聞いていた（今日と明日の2回）→ 日付ごとに6時間キャッシュ。
- キャッシュがなくシート・カレンダーを開く遅いときだけ「読み込み中（…）」を出す（`busStartLoadingIfSlow_`）。保存は必ずシートに書くので常に出す。
- 時刻表データ本体は以前から6時間キャッシュ済み。

残りは GAS の起動と LINE への通信の時間。これ以上速くするには Webhook を Supabase Edge Function に移す。
