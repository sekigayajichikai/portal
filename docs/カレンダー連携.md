# カレンダー連携（回覧板の予定 → 自治会カレンダー）

回覧板ポータルで整えた予定（`event_cards`）を、自治会カレンダー（book-system）の `calendar_events` に載せる仕組み。
管理画面の **予定タブ →「カレンダーに反映」**（2026-09-29 実装）。

## 背景（なぜ作り直したか）

もともと2つのアプリは**別々の Supabase** を使っていたため、次の手作業でつないでいた。

1. 抽出ダイアログの「カレンダー用JSONをコピー」
2. カレンダーアプリの管理画面 → インポートタブ →「JSONを貼り付け」
3. 差分を確認して承認 → `calendar_events` に登録

book-system 側の受け口（`api/import-events.ts` / `CircularCandidates.tsx` / `general_import_rows`）は実装済みだが、
**この手作業が一度も行われず**、カレンダーには会館予約しか載っていなかった（2026-09-29 時点で `general_import_rows` は0件、
カレンダーの今日以降14件はすべて `event_type='facility'`）。

2026-09 に本番DBを統合して**同じプロジェクト（iplc）**になったので、回覧板側から直接書く形に変えた。
旧方式のコードは book-system 側に残っているが、使わない。

## 仕組み

- **流す対象**: 公開済みの号の予定で、日付が今日以降のもの。下書きの号は公開カレンダーに出ないのと同じ扱いで流さない。
  `digest_exclude`（週次配信に載せない）は関係ない。役員向けの会議もカレンダーには載る。
- **紐づけ**: `calendar_events.source_event_card_id` に元の予定カードのIDを入れる
  （`sql/migrations/2026-09-29-calendar-events-source-card.sql`。本番適用済み）。何度流しても二重にならない。
- **カレンダー側だけにある予定（会館予約など）には触れない**。消すこともしない。

### 項目の対応

| 予定カード | カレンダー | 備考 |
|---|---|---|
| event_date | date | |
| title | title | |
| event_time | start_time / end_time | 「10:00-12:00」「13時半」などを解釈（`splitTimeForCalendar`） |
| event_location | location | |
| description | description | |
| organizer | org_name | |
| linked_article_id | article_url | 記事があれば `https://…/?article=<記事ID>`。無ければ空 |
| — | event_type | 常に `general`（会館予約の `facility` と区別する） |
| — | visibility | 常に `public` |

## 使い方

1. 管理画面の **予定タブ**（`/admin?mode=events`）→ 右上の「カレンダーに反映」
2. 差分が4つに分かれて出るので、載せるものを選ぶ
   - **新しく載せる** … カレンダーにまだ無い（既定でチェックあり）
   - **内容を更新する** … 前に載せたあとで回覧板側が変わった。何が変わるかを表示（既定でチェックあり）
   - **カレンダーに似た予定があります** … 同じ日に似た名前の予定がカレンダーにある（会館予約など）。
     載せると二重になるので**既定でチェックなし**
   - **変更なし** … 同じ内容。表示のみ
3. 「カレンダーに反映」を押す

題名や場所が整っていない予定（PDFの読み取りが甘いもの）は、**先に予定タブで直してから**流すとカレンダーがきれいに保てる。

## 載せる前の点検（2026-09-29 追加）

PDF（特にスキャン画像）からの抽出は、題名に紙面の見出しがそのまま入ったり、催しでないお知らせを拾ったりする
（10月号で「乳児&幼児対象」「駐在所管内警察相談所よりお知らせ」「本茶会(茶くやき)」など）。
予定タブと反映ダイアログに、**確認したほうがよい予定の印**を出す。2つの方法を併用する。

| | 機械判定（`eventQualityCheck.ts`） | AIの点検（`checkEventsWithGemini`） |
|---|---|---|
| いつ効くか | 常に（一覧を開くだけ） | 「AIで点検」を押したとき |
| 費用 | ゼロ | Gemini 無料枠で1回（一覧をまとめて送る） |
| 見つけるもの | 題名が3文字未満／末尾が説明語（〜対象・〜のお知らせ）／場所も主催も空／括弧や記号の崩れ／日付が400日以上先 | 題名が催しの名前になっていない、そもそも催しでない、文字の読み違い、日付や場所が原文と合わなそう |

- どちらも **「消す候補」ではなく「目を通す候補」**。印を出すだけで、消すかどうかは人が決める。
- 役員会・監査のように「題名が短く場所も無い正しい予定」を誤って挙げないよう、AIのプロンプトで明示的に除いている。
- 印は赤（⚠ 要確認＝載せる前に直したい）と黄（⚠ 念のため）の2段階。理由は行の下と、印にマウスを乗せると出る。
- Gemini が混んでいる（503）ときは、少し待って再試行し、それでも駄目なら控えのモデル（`GEMINI_FALLBACK_MODEL`）に切り替える。
  無料枠の1日の上限（20回）に達したときは、その旨を出して機械判定だけで続けられる。

## カレンダー側の「表示する団体」フィルタ（2026-09-30 に直したこと）

反映は成功しているのに、カレンダーアプリ（https://sekigaya-calendar.vercel.app）に予定が出ない、という状態だった。
原因は**カレンダー側の絞り込み**で、回覧板から流したデータには問題がなかった。

カレンダーの左側には「表示する団体」のチェックボックスがある。これは会館予約の団体マスタ
（`booking_organizations`）から作られる。ところが絞り込みの判定が
「団体名があって、チェックが入っていなければ非表示」だったため、
**団体マスタに載っていない団体名の予定は、チェックのしようがないまま必ず落ちていた**。

回覧板から流す `org_name` は紙面に書かれた主催者なので、会館を借りない外部団体（地域ケアプラザ、警察署、
選挙管理委員会など）や、表記の違う団体が普通に入る。10月の36件のうち、マスタと一致したのは
「ふれあいの会」の6件だけで、残り30件が画面に出ていなかった。

book-system 側を直した（`src/utils/orgFilter.ts` を追加、`CalendarView.tsx` と `mobile/MobileEventList.tsx`）。

- 団体マスタに**登録がある**団体名 … これまでどおりチェックで表示・非表示を切り替える
- 団体マスタに**無い**団体名 … 「未分類」として扱う（「未分類」のチェックで出し入れできる）

### 残っている表記の違い

カレンダー側の団体マスタと、回覧板側の主催団体の書き方が揃っていない。
上の修正で表示はされるが「未分類」に入るので、団体ごとの絞り込みには出てこない。

| 回覧板側 | カレンダー側の団体マスタ |
|---|---|
| 関ヶ谷クラブ（7件） | 関ケ谷クラブ（小さい「ケ」） |
| 関ヶ谷子供会 | 関ヶ谷こども会 |
| 関ヶ谷自治会（10件） | 「自治会」（グループ名が「自治会」） |

揃えるならどちらの表記に寄せるか決める必要がある（カレンダー側マスタ自体も「関ケ谷読書会」と
「関ヶ谷クラブ句会」が混在している）。

### あわせて気づいた別の問題（未対応）

カレンダーの「表示する団体」の選択は各自のブラウザ（`localStorage` の `filter_orgs`）に保存され、
**一度保存されたあとは団体マスタに新しい団体が増えても追加されない**。
新しい団体の予定が、その人のブラウザでだけ出ないことになる。
「見たことのある団体名」を別に覚えて、新しく現れた団体だけ既定でONにする直し方が要る。
