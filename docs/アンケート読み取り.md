# アンケート読み取り（管理画面「アンケート」タブ）

紙のアンケート回答用紙（スキャン PDF・スマホ写真）を AI（Gemini）で読み取り、人が確認して集計する。
2026-11-21 試作。最初の対象は「西金沢学園地域防災拠点アンケート」（2026-10 配布、16問、○を付ける方式）。
要件定義と試し読みの記録は `D:\ドキュメント\Dev\Jichikai\_private\アンケート回収_2026-11\`（git 管理外。スキャン画像があるため）。

## 使い方（管理者）

1. 管理画面 → 「アンケート」タブ。右上でアンケートを選ぶ（地域の区別は付けない。2026-11-20 はなさん）
2. 「PDF・写真を選ぶ」で回収票を入れる。PDF は1ページ＝1票として画像になる。逆さまの票は自動で直す（外れたら行の「回す」）
3. 「AI で読み取る（N 枚・見込み ○○円）」→ 確認ダイアログで金額を見て実行。1枚 5〜20 秒、混んでいると数分
4. 「要確認」になった票（AI の自信が低い・迷った点がある・白紙）だけ「確認する」で画像と見比べて直し、「確認済み」にする
5. 「集計」で設問ごとの件数と割合。「CSV」で票ごとの一覧を出す（Google フォームの回答との合算は表計算側で）
6. 「AI 利用記録」に、実行ごとの枚数・トークン・見込みと実績の金額が残る（会計への説明用）

## 仕組み

| もの | 場所 |
| --- | --- |
| 設問・選択肢の定義、プロンプト、出力スキーマ | `packages/shared/services/survey/surveyDefinition.ts` |
| 読み取り（Gemini 呼び出し・再試行・費用計算） | `packages/shared/services/survey/surveyReadService.ts` |
| 保存（survey_sheets / ai_usage_log） | `packages/shared/services/data/surveyService.ts` ／ SQL `sql/migrations/2026-11-21-survey-reading.sql` |
| 画面 | `apps/circulars/src/components/admin/survey/`（SurveyPanel・SheetReviewDialog・SurveyTally・sheetImages） |
| 試し読みの道具（画面を通さず手元で読む） | `scripts/survey-test/`（run-survey-gemini.mjs・compare.py・tally.py） |

- モデルは **gemini-3.8-flash**（2026-11-20 の試し読みで 5票77設問すべて一致。○に×の票だけ「自信 低」と理由を返した）。
  混雑（503）は待って再試行、駄目なら 3.6-flash。Flash-Lite は見落としが多く自信も当てにならないので使わない
- 画像は幅 1,240px（150dpi 相当）の PNG。1票 ≈ 入力 1,850 ＋ 思考 600 ＋ 出力 350 トークン ≈ 0.7 円（有料換算）
- **無料枠の注意**: Flash 系は 1日20回、1分5回。503 の再試行も回数に入るので、1日に 10票ほどしか読めないことがある。
  枠は日本時間 17時ごろに戻る。本番は有料枠のキーを推奨（年数回のアンケートでも数百円）。ai-proxy の `GEMINI_API_KEY` を差し替えるだけ
- AI に送るのは用紙の画像だけ。回答用紙は無記名。筆跡が残る縮小画像は survey_sheets に入れ、RLS で管理者だけが読める

## 2026-11-23（日）の会合で見せる手順

- 当日に API を呼ばなくても見せられるよう、手元の試し読み結果を取り込める: 票の一覧の「結果 JSON」に `scripts/survey-test` の結果（`results/*.json`）を入れると、
  画像の名前（`scan1_p02.png` ↔ `scan1_p02`）で突き合わせて読み取り済みにする。画像は先に「PDF・写真を選ぶ」で入れておく
- ライブで見せるなら 3〜5 枚にとどめる（無料枠と 503 の待ち時間のため）
