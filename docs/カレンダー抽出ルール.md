# カレンダー（イベント予定）抽出ルール

回覧板の記事・PDFから、カレンダーに載せるイベント予定（event_cards）をAIで抽出する際のルール。
実装: `packages/shared/services/ai/claudeService.ts`（`extractEventCandidates` / `extractEventCandidatesFromPDF`）、
UI: `apps/circulars/src/components/admin/EventCandidateDialog.tsx`。

## 抽出対象
- **記事テキスト**（記事化された号の記事）と、**添付PDF**（source=自治会のお知らせ / attachment=地域のお知らせ）の**両方**から抽出する。
- 同一イベント（同じ `event_date` + `title`）は重複除去し、記事由来を優先して残す（記事にリンクできるため）。

## 日付・イベントの扱い
- **開催日が特定できるものだけ**抽出（「毎週」「随時」「未定」は除外）。
- 年が書かれていない日付は、回覧板の**発行日以降で最も近い日付**として解釈する（発行日=issue_date は「年の推定」に使う）。
- 行事予定表のように日付が羅列されている場合も1件ずつ抽出する。
- **過去の報告記事（開催済みの報告）は除外**する。
- **過去の予定は抽出しない**: 基準は「**抽出した日（今日）**」。今日より前の日付の予定は候補に出さない（同日は含む）。AIプロンプトでの指示に加え、ダイアログ側でも今日より前を弾く二重ガード。
  - 発行日ではなく「今日」基準にした理由: 過去号をまとめて入力するときも終了済みを自動除外できるため。
- **公開カレンダー表示**でも「今日より前の予定」は非表示（`CalendarView`）。抽出基準に関わらず住民には過去予定が出ない。

## 募集・締切ルール（重要）
- 「募集」「申込」「〆切/締切」などの**締切系の日付は、自治会関連の記事・PDFからのみ抽出**する。
  - 記事: `article_type === 'official'`（自治会のお知らせ）＝自治会関連。
  - PDF: `type === 'source'`（自治会のお知らせ）＝自治会関連。`type` 未設定の旧データは自治会扱い。
- **自治会以外の発行元**（地域のお知らせ＝`local-info` / PDF `attachment`。例: 学校だより、駐在所、にしかぜ 等）からは、
  **募集・申込・締切は予定として抽出しない**。実際に開催されるイベントの**開催日のみ**抽出する。

## イベント種別（category）
イベントの性質ごとにカレンダーの見せ方を変えるため、`event_cards.category` を持つ。AI推定＋抽出ダイアログで手直し。
- `reserve`（要予約）… 予約・事前申込が必要。対象が限られる（地区センター講座 等）。カレンダーで「📝要予約」バッジ。公開カレンダーに「要予約の催しを隠す」フィルタ（既定OFF＝集客のため全表示）。
- `recurring`（連続）… 毎週・定期・全N回（習い事・体操教室・連続講座）。**日ごとに分けず1件に集約**し、次回開催日＋「毎週◯曜」で表す（カード氾濫防止）。「🔁毎週・連続」バッジ。
- `open`（当日参加OK）… 申込不要で当日自由参加（お祭り・サロン）。集客したいので目立たせる（「🎪当日参加OK」バッジ＋色）。
- `null`（一般）… 特に指定なし。

※Phase1は単一種別タグ。連続イベントの本格的な繰り返しルール（毎週◯曜・終了日での自動展開）はPhase2の検討事項。要予約かつ連続（習い事）のような重なりは、より重要な方の種別を選ぶ。

## 主催団体（organizer）
- 主催団体は事前に**マスター登録**（管理画面「主催団体」）しておく。
- 抽出時、登録済みの主催団体名をAIに渡し、**表記を登録名に寄せる**（表記揺れの低減）。
- 抽出ダイアログでは、抽出結果をグレーのタグで表示。クリックで検索付きピッカー（Notion風）を開いて選び直し・新規登録が可能。

## 出典リンク
- 各イベントは**由来PDF**（`event_cards.source_pdf_url`）を記録し、カレンダーの「元のPDFを見る」はその**実際の抽出元PDF**へリンクする（号の先頭PDF固定をやめた）。
- 記事にリンクできる場合は「記事を読む」を優先表示、無ければ由来PDFへのリンクを表示する。

## 関連DBカラム（iplc / sekigaya-portal）

- `event_cards.source_pdf_url TEXT` … 由来PDFのURL
- `organizers` テーブル … 主催団体マスター

## v4（2026-09-07）で追加したルール
実装は `packages/shared/services/ai/eventExtractionPrompt.ts`（Claude/Gemini 共通）。本番の抽出は Gemini 2.5 Flash（`docs/AIコスト・モデル方針.md`）。

### 催しでないもの・内部行事の除外
- 啓発期間・キャンペーン期間・「○○の日」「○○週間」「強化月間」・休館日・受付時間・営業時間・工事期間は「参加する催し」ではないので抽出しない（駐在所だよりの交通安全運動などが対象）。
- チラシが「〜からのご案内」等のセクションに分かれている場合、見出しを判断材料にする。「通所介護（デイサービス）」「保育園」「学校」など施設の利用者・在籍者向けセクションの月間予定（お誕生日会・体操教室・作品作り等）は除外。
- 対象が属性で絞られていても（介護者・子育て中・65歳以上）、一般に開かれた案内があれば抽出する。除外するのは「その施設の利用者しか参加できないもの」だけ。

### 名称・複数日付
- **title は原文どおり**（別記事の語を混ぜない、内容から名前を作らない）。合成名（例: ジャンケンポン歌う会）の防止。
- 同じ囲みに開催日が複数並ぶもの（例: 9/25・10/23）は recurring 1件にまとめ、他の日付は `event_time` 末尾に「（10/23も）」と補記。
- `source_text` に名称と日付が書かれた原文の一節（40字以内）を付ける。合成名の検出に使う（OCR 由来の誤読は防げない）。

### 性質（kind）
配信・表示での扱いを分けるための区分。`event_cards.kind`。
- `community`（地域交流の催し）… 祭り・芸術祭・発表会・講演会・季節行事・「だれでも参加」の集まり。週次配信のトピックになりやすい。
- `support`（福祉・健康・生活支援の案内）… 健康測定・体力測定・相談会・介護者や家族向けのつどい・予防講座。見出しが「地域包括支援センター」「居宅介護支援」等の配下は原則 support。カレンダーには載せるが、配信では「お知らせ」枠扱い。
- `class`（定例教室・講座・サロン）… 毎週/毎月の習い事、連続講座、カフェ・サロン。
- `null` … どれでもない。

### 週次配信トピック（weekly_topic）
公式LINEの「今週のお知らせ」で取り上げる候補。`event_cards.weekly_topic` / `topic_reason`。
最終判断は人（抽出ダイアログの ⭐ トグル）。付与の優先順は次のとおり。
1. **複数掲載**（機械判定）… 同じイベント（日付＋正規化したタイトル先頭8文字）が記事とPDFの両方、または2本以上のPDFに載っている → true、根拠「複数掲載」。
2. **単独チラシ**（機械判定）… 1本のPDFから抽出されたイベントが1件だけ（＝そのイベントのためのチラシ）→ true、根拠「単独チラシ」。
3. **AI判定**（補助）… community で年数回の目玉・「だれでも参加」なら true。support / class は原則 false。機械判定に当たらない support はダイアログ側で false に倒す（AIの甘い判定を抑える）。

### 申込締切（apply_deadline）— 2026-09-08 追加
週次配信（`docs/週次配信.md`）で「申込受付中」「締切間近」を組むための属性。`event_cards.apply_deadline DATE`。
- 締切は **イベントの属性** として持つ。要予約（reserve）や定員制の連続講座に「締切 10/16」「申込は◯日まで」とあれば `apply_deadline` に入れる。
- 「地域PDFから締切だけの独立カードは作らない」ルールはそのまま。属性としては地域PDFからも拾う（にしかぜの講座の締切など）。
- 「先着順」の属性は一度入れたが、AI の判定が実行ごとに揺れて活きないため廃止（2026-09-08）。締切なしの要予約は配信側で「開催7日前」を仮締切にする。
- 締切があるのに種別が「当日OK」や未設定の候補は、解析時に「要予約」へ補正する（AI の揺れ対策）。
- 締切が読めない要予約は空欄のまま登録し、配信側で「開催7日前」を仮締切にして「頃」を付ける。抽出ダイアログの「締切」欄で手入力できる。
- マイグレーション: `sql/migrations/2026-09-08-event-cards-deadline.sql`

### 対象者（target_audience）・参加費（fee）— 2026-09-08 追加
週次配信で「⭐一押し」「📝申込受付中」の行に「（65歳以上・無料）」と添えるための属性。`event_cards.target_audience TEXT` / `fee TEXT`。
- 対象者は参加できる人の条件を原文どおり短く（「65歳以上」「乳幼児＆幼児」「成人」）。定員は含めない。
- 参加費は「無料」「400円/回」「3,200円（2回分）」のように短く。書かれていなければ空。
- どちらも抽出ダイアログで手直しできる。公開カレンダーでの表示は未対応（次の候補）。
- マイグレーション: `sql/migrations/2026-09-08-event-cards-audience-fee.sql`

### 紹介文（description）— 2026-09-21 追加
週次配信の「⭐一押し」でタイトルの下に添える1〜2文の紹介文。`event_cards.description TEXT`。予定の個別ページ（`/?event=<ID>`）にも表示する。
- 「何をする催しか・どんな人におすすめか」を60字以内で。日時・場所・対象・費用は別項目に入るので繰り返さない。
- 原文に内容説明が無く日時・場所しか書かれていなければ空（null）。
- 抽出ダイアログ（textarea）と予定カードの編集で手直しできる。追加抽出の「空欄だけ補完」の対象。
- マイグレーション: `sql/migrations/2026-09-21-event-cards-description.sql`

### 種別（category）の優先順 — 2026-09-08 更新
- 「申込不要」「予約不要」「当日直接」と明記されていれば、定例・複数日付でも **open（当日OK）** にする（例: みんなの健康体操、おひざの上のお話会、おもちゃ病院）。
- 申込先・締切・定員の記載があるものは **reserve**。締切があるのに open/未設定で返ってきた候補は解析時に reserve へ補正する。
- 申込の要否が書かれていない定例のものだけ **recurring**。複数日付の1件集約は category に関わらず行う。

### 性質（kind）の優先順 — 2026-09-08 更新
- セクション見出しを最優先。「地域包括支援センター」「居宅介護支援」「保健」「福祉」配下は support。
- 「地域交流からのご案内」など一般向けセクションのものは、健康・予防がテーマでも community か class（例: 転倒予防の体操教室 → class）。
- 見出しが無い場合は、相談会・介護者や家族向け・健康測定など「支援を受ける人向け」だけ support。
